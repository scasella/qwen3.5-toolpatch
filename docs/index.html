      2. 
      
        Load the models
        
      
        One download serves both models: the fp16 decoder (≈1.5 GB) plus 4-bit embeddings (≈150 MB), cached by your browser in 64 MB chunks. The edited model is produced in memory by writing the 12,281 edited values into the layer-22 and layer-23 MLP tensors of the downloaded original; the SHA-256 of the result is checked against the published edited file.
        
      
        
        
        
        
      
        
      
        
      
        Why fp16 and not a ~650 MB 4-bit build
        The edit reads directions in the residual stream that were fitted on the BF16 model. With a q4 backbone that input drifts (cosine ≈0.89 to the BF16 activations on the same prompts) and the gates stay closed, so the neurons never fire; measured by scripts/export_webgpu_onnx.py --drift (report: webgpu_export_report.json). The layer-22 and layer-23 MLP tensors are kept in fp16 so block quantization cannot distort J0, J1, J2 or J3.
        
      
        The live runner uses an ONNX export, not the campaigns' BF16 MLX weights. Treat its outputs as a demonstration; the token-identical claims in the blog post refer to the recorded runs in the first mode.
